The challenge

Official data is revised.
Constantly.

📡

First release

Preliminary figures, incomplete reporting. Published to meet calendar deadlines.

🔄

Revision cycle

Updated as more reports arrive. Seasonally adjusted. Benchmark-revised. The past keeps changing.

🕳️

Most tools

Overwrite the series. No revision history. No way to reconstruct what analysts knew — and when.

Forecast evaluation and economic research depend on knowing the real-time data vintage — the exact information set available at each point in time.

Our framework

Three core contributions

📦

Consumer package

R package enabling researchers to access well-documented, machine-readable time series with minimal friction.

🏗️

Provider boilerplate

A framework for organizations to publish their own time series following consistent, open standards.

⚙️

Hosting strategy

Fully automated, reproducible updates via CI/CD. Cost-free hosting on GitHub. No servers needed.

The killer feature

Time travel. Built in.

Query a series as it was known on any given date. Every vintage is preserved, accessible, and citable.

  • Real-time databases for forecast evaluation
  • Vintage-aware reproducibility
  • Study revision patterns in official statistics
  • Cite the exact data state you used
# Latest vintage (default) read_ts("ch.kof.tour.guest_nights") # Exact release date read_ts("ch.kof.tour.guest_nights", vintage = "2023-02-15" ) # Inspect revision history vintages("ch.kof.tour.guest_nights") #> vintage 2022Q1 2022Q2 2022Q3 #> 2023-02-15 96 86 138 #> 2023-08-22 99 90 143

Human-readable, diff-friendly, editor-agnostic. Works in any language.
